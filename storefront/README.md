# Dream Storefront — החזית של החנויות (2.55.0)

האתר שהלקוחות של העסק רואים. אפליקציה אחת לכל העסקים: **החנות נקבעת לפי הדומיין** של הבקשה.

- **המסד:** קוראת רק לפונקציות `sf_*` (מיגרציה `20261005003400_commerce_store.sql`), ורק מהשרת שלה. לא קוראת שום טבלה, ולא מייבאת קוד מהדשבורד. `tests/unit/no-tables.test.ts` בודק את זה בקוד.
- **הלקוח לא רואה את Dream:** אין בקוד של האתר את המילים Dream או דרים.
- **שינוי בדשבורד מופיע מיד:** כל עמוד נבנה בכל בקשה, בלי cache — מחיר, תמונה, מלאי, עיצוב ותפריט.
- **בשלב 2 אין קנייה.** אין עגלה ואין תשלום. מוצר מוביל לוואטסאפ של העסק, או ל"יצירת קשר".

**טכנולוגיה:**
- Next.js 16.3.8, React 19.3, TypeScript 5.9.
- CSS רגיל (קובץ אחד, `src/app/globals.css`), בלי Tailwind.
- הגופן Heebo מקומי (`@fontsource-variable/heebo`), בלי בקשה ל-Google Fonts.
- ב-Next 16 קובץ ה-middleware נקרא `src/proxy.ts`.

## איך זה עובד

1. **`src/proxy.ts`:**
   - מנרמל את ה-Host: אותיות קטנות, בלי פורט, ודומיין בעברית ב-punycode.
   - מוחק כותרות `x-sf-*` שהגיעו מבחוץ.
   - מנתב פנימה ל-`/site/<host>/<path>`.
   - קובע CSP עם nonce לכל בקשה.
   - **`?preview=<token>`:** אסימון חתום מהדשבורד. נשמר בעוגייה `sf_preview` (httpOnly), והכתובת מתנקה.
2. **`sf_resolve_host`:** איזו חנות היא הדומיין הזה.
   - **דומיין לא מוכר:** 404 ניטרלי.
   - **www, או דומיין משני:** 308 לדומיין הראשי.
   - **חנות בטיוטה או מושהית:** עמוד "בקרוב", חוץ מתצוגה מקדימה עם אסימון של אותה חנות.
3. **"פעיל":** הפעם הראשונה שהחזית מגישה עמוד בדומיין (`sf_domain_seen`, אחרי התשובה) מסמנת אותו "פעיל" בדשבורד. כך "פעיל" אומר שה-DNS וה-SSL באמת עובדים, ולא רק ש-Vercel קיבל את הדומיין.
4. **כתובות של Vercel** (`*.vercel.app`) ו-localhost: לא חנות של אף עסק. רק תצוגה מקדימה שאסימון פתח.
5. **התבנית "שקיות ממותגות"** (`src/templates/bags.ts`): הגדרות בלבד, בלי קוד.
   - העיצוב שנשמר בדשבורד נבדק שדה-שדה מול הסכמה (`src/lib/theme.ts`).
   - ערך שלא מתאים מוחלף בערך של התבנית.
   - טקסט ורקע עם ניגודיות נמוכה מ-4.5:1 חוזרים לצבעים של התבנית.
6. **SEO:**
   - `sitemap.xml` ו-`robots.txt` לכל דומיין.
   - canonical לדומיין הראשי, Open Graph, ו-JSON-LD: Organization, Product, BreadcrumbList.
   - תג האימות של Search Console, כשהוזן.
   - הפניה 308 מכתובת ישנה (`sf_redirect`).
   - חיפוש ומסננים: `noindex, follow`.
7. **GA4:** נטען רק אחרי "מאשר/ת" בחלונית העוגיות (העוגייה `sf_consent`). "הגדרות עוגיות" בתחתית מאפשר לחזור בו.

## פקודות

| פקודה | מה |
|---|---|
| `npm ci` | התקנה (ה-lockfile ב-git) |
| `npm run dev` | פיתוח, פורט 3230. צריך `SUPABASE_URL` ו-`SUPABASE_SECRET_KEY` |
| `npm run typecheck` | TypeScript |
| `npm test` | בדיקות יחידה: נרמול host, אסימון תצוגה (אותו וקטור כמו בדשבורד), תבנית וסכמה, מחירים ופורמטים, ובדיקת "אין טבלאות" |
| `npm run test:e2e` | **דפדפן מול Postgres אמיתי:** בונה את האפליקציה, מקים את המסד `sf_e2e` מכל המיגרציות של הדשבורד + `tests/e2e/seed.sql`, ומריץ Chromium. צריך Postgres 16 מקומי (כמו `npm run test:sql` בדשבורד) |
| `npm run build` | בנייה ל-production |

**ההרצה המקומית של הבדיקות** (`SF_DATA=pg`): אותן פונקציות `sf_*`, בחיבור Postgres בתפקיד `service_role`. הקוד מסרב לרוץ כך ב-Vercel.

## הקמה ב-Vercel — פעם אחת, על ידי בעל המערכת

1. **פרויקט:** Vercel ← Add New ← Project, מאותו repo.
   - **Root Directory:** `storefront`.
   - **Framework:** Next.js (מזוהה לבד). Node 20 ומעלה.
   - **אזור:** `fra1`, קרוב למסד ב-eu-central-1 (כבר ב-`vercel.json`).
2. **משתני סביבה** (Production ו-Preview):

   | משתנה | ערך |
   |---|---|
   | `SUPABASE_URL` | הכתובת של פרויקט ה-Supabase — אותה כתובת כמו `NEXT_PUBLIC_SUPABASE_URL` בדשבורד |
   | `SUPABASE_SECRET_KEY` | מפתח שרת של אותו פרויקט (Secret key, או `service_role` הישן). **סוד: רק ב-Vercel, לעולם לא בקוד** |
   | `STOREFRONT_PREVIEW_SECRET` | מחרוזת אקראית של 32 תווים ומעלה. **אותו ערך בדיוק בשני הפרויקטים** |
   | `STOREFRONT_PLATFORM_HOSTS` | לא חובה: כתובות נוספות של החזית שאינן חנות, מופרדות בפסיק |

3. **Deploy.** הכתובת `….vercel.app` של הפרויקט לא מציגה חנות, אלא רק תצוגה מקדימה מהדשבורד.

**בפרויקט הקיים של הדשבורד** מוסיפים:
- `STOREFRONT_URL`: הכתובת `https://….vercel.app` של פרויקט החזית. משמשת לתצוגה מקדימה, עד שהדומיין פעיל.
- `STOREFRONT_PREVIEW_SECRET`: אותו ערך.
- **לא חובה — הוספת הדומיין ל-Vercel מהדשבורד:**
  - `VERCEL_API_TOKEN`: טוקן של חשבון ה-Vercel.
  - `VERCEL_STOREFRONT_PROJECT`: השם או המזהה של פרויקט החזית.
  - `VERCEL_TEAM_ID`: רק אם הפרויקט בצוות.
  - בלי המשתנים האלה מוסיפים את הדומיין ב-Vercel ביד (למטה).
  - **החיבור הזה לא אומת מול Vercel.** הבקשות נכתבו לפי התיעוד, ונבדקו רק מול תשובות מדומות.

**בנייה רק כשצריך:** `ignoreCommand` בשני ה-`vercel.json` משווה ל-commit של הפריסה המוצלחת האחרונה (`VERCEL_GIT_PREVIOUS_SHA`). שינוי שלא נגע בתיקייה של פרויקט לא בונה אותו. אם ההשוואה לא מצליחה, הפרויקט נבנה.

## הדומיין followmecollection.com

1. **בדשבורד:** חנות ← הגדרות ודומיין ← דומיין ← `followmecollection.com` ← "חיבור". `www.followmecollection.com` מצטרף לבד.
2. **ב-Vercel**, בפרויקט החזית: Settings ← Domains ← Add.
   - מוסיפים את `followmecollection.com`.
   - מוסיפים את `www.followmecollection.com`, עם Redirect אל `followmecollection.com`.
   - כש-`VERCEL_API_TOKEN` מוגדר בדשבורד, הוא עושה את זה בעצמו.
3. **אצל רשם הדומיין** (DNS): מוסיפים את הרשומות ש-Vercel מציג במסך Domains.
   - בדרך כלל: A ל-`@`, ו-CNAME ל-`www`.
   - המסך בדשבורד מציג את ערכי ברירת המחדל של Vercel, ומסמן שהם כאלה. **הערכים המדויקים הם אלה שב-Vercel.**
4. **פתיחה:** אחרי שה-DNS מתעדכן (לפעמים כמה שעות), פותחים את `https://followmecollection.com` פעם אחת.
   - הדומיין מסומן "פעיל" בדשבורד.
   - רק אז אפשר "העלאת החנות לאוויר", וגם כל שאר הרשימה צריכה להיות מושלמת: פרטי עסק, יצירת קשר, שלוש מדיניות, ומוצר אחד באתר.
5. **Search Console:**
   - מוסיפים נכס, ובוחרים אימות בתג HTML.
   - מדביקים את התג בדשבורד, בהגדרות ← גוגל.
   - אחרי שהחנות באוויר: Verify, ואז Sitemaps ← `/sitemap.xml`.
6. **GA4:** מזהה המדידה (`G-…`) בהגדרות ← גוגל.
