## 1. מה זה

אפליקציית שיווק מבוססת AI לעסקים קטנים בישראל (עברית, RTL, מותאם לטלפון):
יצירת רילס ופוסטים, קריינות בעברית, כתוביות, ספריית מדיה, יומן, ופרסום לאינסטגרם, פייסבוק ו-TikTok.

**סטאק:** Next.js 14 (App Router) · TypeScript · Tailwind · Zustand · Supabase (Auth, Postgres, Storage, pg_cron) · Vercel (Hobby).
**ספקים חיצוניים:** Anthropic (טקסט) · fal.ai (תמונות Nano Banana 2, וידאו Wan, תמלול Whisper) · ElevenLabs (קול) · Meta Graph API v23 · TikTok Content API · Openverse (מוזיקה) · Alibaba Model Studio (וידאו, כתוב אבל לא מופעל).

היקף: 138 קבצי TS/TSX, כ-13,300 שורות.

## 3. ארכיטקטורה — הנקודות החשובות

- **ספקי AI:** `src/lib/server/ai/`
  - `config.ts`: המקום היחיד עם שמות ספקים, מודלים ומחירים.
  - `router.ts`: ניסיון חוזר אחד על שגיאה זמנית, fallback רק לפי כלל, ורישום של כל ניסיון.
  - `providers/fal.ts`, `providers/alibaba.ts`.
- **ספר עלויות:** טבלת `ai_generations`, עם views בשם `reel_costs` ו-`provider_health`. העלויות מחושבות בשרת בלבד.
- **מכסות:** `src/lib/server/quota.ts` + RPC `reserve_usage` / `commit_usage` / `release_usage` / `finish_usage`. הנעילה היא per-user advisory lock, כך שבקשות מקבילות לא עוקפות את המכסה.
- **הורדות בשרת:** `src/lib/server/safe-fetch.ts`: רשימת hosts מותרים, חסימת IP פרטי, בדיקה מחדש של כל redirect, ותקרת גודל.
- **רינדור הריל:** `src/lib/server/reel-render.ts` (ffmpeg-static):
  - נורמליזציה ל-720×1280.
  - Ken Burns עם zoompan.
  - ducking של מוזיקה מתחת לקול.
  - הכתוביות מצוירות בדפדפן כ-PNG שקוף במסך מלא, ומצורפות ב-ffmpeg כ-concat track אחד.
- **אולפן הרילס:** `src/app/(app)/reels/page.tsx` (הקובץ הגדול בפרויקט) + `src/features/reels/`.
- **פרסום מתוזמן:** `src/lib/server/scheduler.ts`. כל ריצה תופסת שורות עם `locked_until`, ויעד שכבר הצליח לא נשלח שוב.
- **Meta:** `src/lib/server/meta.ts`: OAuth, טוקנים מוצפנים (AES-256-GCM), container לאינסטגרם, `/videos` לפייסבוק, ייבוא סטוריז ופוסטים.

## 4. מה נבדק, ואיך

- פרסום ריל לעמוד פייסבוק ולאינסטגרם במקביל: עבד.

- ספריית מוזיקה מ-Openverse: עובד, אחרי תיקון `page_size ≤ 20` לבקשות אנונימיות.
- יצירת קליפ, טיוטה, ריל סופי ופרסום: עבד.
- טיימר הסטוריז (pg_cron): עבד, אחרי איפוס CRON_SECRET.

**נבדק כאן (sandbox), לא מול השירות האמיתי:**
- `npm run typecheck` ו-`npm run build`: exit 0 בכל גרסה.
- כל המיגרציות רצו פעמיים על PostgreSQL 16 אמיתי (idempotent).
- מכסה אטומית: 10 בקשות מקבילות עם מכסה ל-3, ועברו בדיוק 3.
- רינדור ffmpeg אמיתי: הפריים הראשון לא שחור, Ken Burns זז (סצנת ביקורת סטטית בהפרש 0), כתוביות בזמנים הנכונים.
- SSRF: חסימת localhost, 169.254.169.254, IP פרטי ו-redirect ל-host לא מורשה. נבדק מול GitHub אמיתי.
- AI Router: 7 תרחישים מול תשובות מדומות (throttle, policy, fallback, יכולות ספק).
- דוח עלויות, publisher מתוזמן (3 ריצות), ניתוח שעות מומלצות, סינון קולות: כולם מול נתונים מדומים.

**לא נבדק בכלל:**
- Alibaba Wan ישיר. אין מפתח. הבקשה נכתבה לפי התיעוד הרשמי.
- פרסום מתוזמן מקצה לקצה. הטבלה והטיימר הותקנו, אבל ריצה מוצלחת של `publish-due` עוד לא אומתה.
- TikTok שליחה לטיוטות מתוך התזמון.
- האשף והמסכים החדשים לא נבדקו בדפדפן על ידי הכותב, רק על ידי המשתמש דרך צילומי מסך.

## 4א. V2.30 שלב A — תוצאות (מה רץ בפועל)

**תיקונים:**
1. **תמלול בלי מכסה (באג):** `/api/transcribe` עובר עכשיו דרך `reserveUsage` → `commitUsage` / `releaseUsage`, עם מכסה חודשית (`QUOTA_TRANSCRIBE_MONTH`, ברירת מחדל 150), הגבלת מקביליות ובקשות לדקה. הקלטה מוגבלת ל-4MB. נוסף ל-ledger: משך האודיו ועלות.
2. **פערים נוספים שהביקורת מצאה וסגרה:**
   - טקסט AI (`/api/ai`): מכסה של 3,000 בקשות בחודש, 6 במקביל, 30 לדקה, ותקרת קלט של 60k תווים.
   - רינדור סופי: רינדור אחד במקביל, 4 לדקה, 300 בחודש.
   - מיגרציה `20261002000700` מוסיפה `transcribe`, `text` ו-`render` ל-`usage.kind`. היא רצה פעמיים על Postgres 16, והבדיקה אישרה שרינדור שני בזמן שאחד פתוח נחסם (`too_many_running`).
3. **שעת תזמון (באג):** השעה חושבה לפי אזור הזמן של הדפדפן. עכשיו `src/lib/il-time.ts` ממיר תמיד משעון ישראל, כולל מעבר שעון קיץ/חורף, וההצגה היא בשעון ישראל. נבדק עם דפדפן מדומה ב-4 אזורי זמן (Jerusalem, New York, UTC, Tokyo), על 5 תאריכים שכוללים את ימי מעבר השעון. כל ההמרות חזרו נכונות.
4. **חיזוק הפרסום המתוזמן** (`scheduler.ts`):
   - שגיאה זמנית (רשת, 5xx, rate limit) מנוסה שוב בריצות הבאות, עד 3 פעמים.
   - שגיאה קבועה (הרשאה, פרמטר לא תקין, read-only) נכשלת מיד.
   - פוסט שמאחר ביותר מ-24 שעות נכשל עם הודעה, ולא מתפרסם באיחור.
   - לוג לכל יעד.
   - **סימולציה:** שתי ריצות טיימר במקביל לא פרסמו את אותו פוסט פעמיים (פרסום יחיד). יעד עם שגיאת רשת פורסם בניסיון השלישי. שגיאה קבועה נכשלה מיד. ריצה רביעית לא תפסה כלום.
   - **לא נבדק מול Meta אמיתי** (ראו שלב D).
5. **עלות לתוצאה מוצלחת:** במסך הניהול, לכל ספק ומודל מוצגים ניסיונות, הצלחות, כישלונות, ניסיונות חוזרים, fallbacks, הוצאה, ועלות לתוצאה מוצלחת. נבדק מול ledger מדומה.
6. **הורדות אינסטגרם** (ייבוא סטוריז ופוסטים) עוברות עכשיו דרך `safeFetch`, עם CDN מורשה בלבד (`*.cdninstagram.com`, `*.fbcdn.net`), תקרת 300MB וזמן קצוב. מארח מזויף כמו `fbcdn.net.attacker.com` נחסם.

**ביקורת RLS (Postgres 16, עם role בשם authenticated ו-auth.uid() אמיתי מה-JWT claim):**
- משתמש A ניסה לקרוא נתונים של משתמש B בכל הטבלאות: profiles, brands, content, media, leads, social_accounts, social_posts, ai_generations, usage, scheduled_posts, וה-views reel_costs ו-provider_health. **בכל מקום קיבל 0 שורות.**
- UPDATE ו-DELETE על שורות של B שינו 0 שורות. INSERT בשם B נחסם ב-RLS.
- גם B עצמו לא רואה את טוקני הרשתות שלו מהדפדפן, כי הטבלה server-only. `anon` רואה 0 שורות.
- דפדפן לא יכול להפעיל את `reserve_usage`.
- **לא נבדק:** מדיניות ה-Storage (bucket) מול Supabase אמיתי.

**ביקורת סודות:**
- הקוד משתמש רק במשתני `NEXT_PUBLIC_*` הבאים: URL ו-anon key של Supabase, גרסה, תאריך build, ומייל ליצירת קשר.
- אף קובץ `'use client'` לא קורא משתנה סביבה שאינו ציבורי, ואף קובץ כזה לא מייבא מ-`lib/server`.
- ב-bundle שנשלח לדפדפן מופיעים רק **שמות** משתנים, בהודעות עזרה בעברית כמו "הגדירו ANTHROPIC_API_KEY". אין ערכים.
- תשובות API לא מחזירות stack או env.
