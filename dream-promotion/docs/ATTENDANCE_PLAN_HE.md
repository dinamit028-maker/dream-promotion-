# נוכחות ועובדים — התוכנית (אושרה ב-23.10.2026)

המשימה: `docs/ATTENDANCE MODULE TASK HE.md`. כל שלב — branch ו-PR משלו, לא מתחילים שלב לפני שהקודם מוזג.

## עקרונות שהמסד שומר (לא רק המסכים)

- **שום רישום שעות לא נמחק.** טריגר `att_no_delete` מסרב למחיקה בכל טבלאות הנוכחות — גם בשרשרת (cascade). עובד שעזב = לא פעיל + תאריך סיום.
- **רישום לא נכתב מחדש.** רישום יכול רק לקבל יציאה (פעם אחת), או להתבטל (פעם אחת, עם סיבה). תיקון של מנהל = הרישום הישן מבוטל + רישום **חדש** שאומר מה הוא מחליף (`replaces`). הסיבה חובה.
- **היסטוריה מלאה:** כל רישום, יציאה וביטול נכתבים ב-`time_entry_events` בטריגר — מי, מתי, לפני, אחרי, סיבה, ומאיפה (השעון / האפליקציה).
- **רק דרך הפונקציות:** משתמש באפליקציה לא כותב רישום, בקשה, היעדרות או חודש ישירות — רק דרך `att_*` (שבודקות הרשאה וסיבה). השעון של העובד (השרת) נכנס ויוצא בדיוק כמו קודם.
- **חודש סגור = נעול** לכל כתיבה של אותו עובד באותו חודש. נסגר רק אחרי שהחודש נגמר, ורק בלי משמרת פתוחה ובלי בקשה או היעדרות שממתינות. פתיחה מחדש — מנהל בלבד, עם סיבה, נרשם.
- **שעות:** כל החישובים בפונקציה טהורה אחת (`features/attendance/hours-engine.ts`), בשעון ישראל, עם בדיקות. הכללים של השעות הנוספות — רק ב-`features/attendance/overtime-rules.ts`.

## הרשאות (`att_role`)

| מי | מה |
|---|---|
| בעלים / editor (ומנהל-העל) | מנהל נוכחות: הכול |
| `attendance_role = 'approver'` | רואה ומאשר רק את העובדים שהוגדרו לו (מחלקה או עובד), מתקן אותם; לא סוגר חודש |
| `attendance_role = 'payroll'` | רואה החשבון / שכר: קורא הכול (גם ת״ז ושכר), לא כותב |
| viewer | קורא (בלי ת״ז ושכר) |
| קופאי/ת | כלום (כמו קודם) |

את `attendance_role` קובע מנהל-העל (מסך הניהול).

## שלב 1 — ליבת הנוכחות (`feature/attendance-core`)

1. מודול "נוכחות ועובדים" (`ATTENDANCE_MODULE`): לוח בקרה, עובדים, מחלקות ומאשרים, דוח חודשי לעובד, אישורים (בקשות, היעדרויות, חודשים), היעדרויות, דוחות וייצוא, הגדרות (מסלולים, QR).
2. עובדים: כל השדות, ארכיון במקום מחיקה, זימון בוואטסאפ עם הקישור האישי, ייבוא מאקסל (רק הוספה).
3. דוח חודשי לעובד: שורה לכל יום, סוג יום עברי, תקן, כניסה / יציאה ואיך, יומי, מצטבר, חוסר באדום, היסטוריה.
4. תיקון מנהל עם סיבה; סגירת יציאה חסרה; ביטול; בקשת עובד → אישור.
5. אישור חודש (מאשר) וסגירה (מנהל), פתיחה מחדש עם סיבה.
6. היעדרויות: רישום של מנהל (מאושר מיד), בקשה של עובד (ממתינה — המסך לעובד בשלב 2).
7. לוח בקרה יומי וחודשי.
8. ייצוא: אקסל ו-PDF לדוח חודשי, CSV לתוכנת שכר.
9. בדיקות: מנוע השעות (חצות, סוף חודש, שעון קיץ / חורף, כניסה בלי יציאה, שתי משמרות, הפסקות, שבת וחג); SQL (המסלול המלא, הרשאות, נעילה, אין מחיקה); השוואה לפני ואחרי 5800; e2e למסלול.

## החלטות שעוד פתוחות (לא מנחשים)

1. **שעות נוספות:** מסלולי התקן של הלקוח; סף יומי בלבד או גם שבועי; 125% לשעתיים ואז 150%; שבת וחג; שעות נוספות בשבת; משמרת לילה; הסכם קיבוצי / צו הרחבה. עד התשובה — הכללים ב-`overtime-rules.ts` מסומנים "ממתין לאישור", העמודות מוצגות כטיוטה, וקובץ השכר לא יוצא.
2. **הפסקות:** ניכוי אוטומטי (כמה ומאיזה אורך יום) או רק לפי יציאה וכניסה. ברירת המחדל עכשיו: בלי ניכוי.
3. **משמרת שחוצה חצות / סוף חודש:** עכשיו — כולה ביום (ובחודש) שבו התחילה, כמו השעון היום.
4. **עיגול:** עכשיו — בלי עיגול (דקות).
5. תוכנת השכר של הלקוח ופורמט הייבוא שלה; קובץ ייצוא לדוגמה מ-OK2GO.
6. מי מנהל ומי מאשר אצל הלקוח.
7. הלקוח הראשון: עסק חדש נוכחות-בלבד, או עסק קיים.
8. תגי NFC: NTAG213 או NTAG 424 DNA.
9. `employees.hourly_rate` הישן נשאר בטבלה שכל הצוות קורא — השכר החדש ב-`employee_private`. לנקות את הישן (שינוי נתונים) — רק באישור.
