# Dream Promotion — בדיקות חיות (שלב D)

הבדיקות כאן צריכות חשבונות אמיתיים, מפתחות או מכשיר, ולכן אי אפשר להריץ אותן בסביבת הפיתוח.
כל בדיקה כוללת מה עושים, מה אמור לקרות, ומה לצלם אם זה לא קורה.
**אחרי כל בדיקה, סמנו ✅ או ❌, וצרפו צילום מסך לכל ❌.**

לפני שמתחילים, ב-Supabase:
- כל המיגרציות רצו, מ-100 עד 800.
- `cron-stories.sql` ו-`cron-publish.sql` רצו עם אותו `CRON_SECRET` שמוגדר ב-Vercel.

## 4. חשבון חדש מאפס

אימייל חדש (לא משתמש קיים):
הרשמה ← הרשמה ראשונית (5 שלבים) ← העלאת לוגו ו-2 תמונות ← חיבור Meta ← פוסט ראשון ← תמונת AI ← ריל (תסריט ← וידאו ← קריינות או בלי ← מוזיקה ← ריל סופי) ← שמירה ← יומן ← תזמון.

- **בכל צעד:** האם ברור מה לעשות? רשמו כל מקום שבו נתקעתם או התלבטתם.
- **אחרי סגירה ופתיחה של האפליקציה:** **לא** חוזרים להרשמה הראשונית. זה באג שנמצא ותוקן ב-2.30.3, ויש לוודא אותו בפרודקשן.

## 5. ספקי וידאו (כשיש מפתחות)

**Alibaba:**
1. ב-Vercel: `DASHSCOPE_API_KEY`, ו-`DASHSCOPE_BASE_URL` של האזור של המפתח. ב-Singapore ברירת המחדל מתאימה. בחשבון workspace הכתובת היא `https://<WorkspaceId>.ap-southeast-1.maas.aliyuncs.com/api/v1`.
2. ניהול ← השוואת ספקים ← לסמן **alibaba** + **fal** ← 5 שניות ב-720p ← הרצה.
3. לרשום: הצליח או נכשל, זמן, איך הסרטון נראה. אם נכשל, לצלם את השגיאה. היא מגיעה ישירות מ-Alibaba.

**Higgsfield:**
1. ב-Vercel: `HF_API_KEY_ID` ו-`HF_API_KEY_SECRET`, מ-console.higgsfield.ai. אופציונלי: `HIGGSFIELD_WAN3_USD_PER_SEC_720P`, לפי המחירון שבקונסול.
2. השוואת ספקים ← **higgsfield** + **fal** ← אותו פרומפט.
3. אם הסרטון נוצר אבל לא נשמר בספרייה, ייתכן שהקבצים שלהם מגיעים מ-CDN אחר. צלמו את כתובת הסרטון, ונוסיף אותה ל-`ASSET_HOSTS`.

**רק אחרי בדיקה מוצלחת:** `AI_VIDEO_PRIMARY=alibaba` או `higgsfield`. fal נשאר תמיד גיבוי.

## 6. אבטחה, ב-Supabase האמיתי (RLS)

ב-SQL Editor, עם ה-uuid של משתמש A (מ-Authentication ← Users). הבדיקה רצה בתוך טרנזקציה שמתבטלת, כך שלא משתנה כלום:
```sql
begin;
set local role authenticated;
select set_config('request.jwt.claims', json_build_object('sub', '<UUID של A>', 'role', 'authenticated')::text, true);
select set_config('request.jwt.claim.sub', '<UUID של A>', true);
select 'media של אחרים' as t, count(*) from public.media where user_id <> '<UUID של A>'
union all select 'content של אחרים', count(*) from public.content where user_id <> '<UUID של A>'
union all select 'טוקני רשתות (כולל שלי)', count(*) from public.social_accounts
union all select 'עלויות AI של אחרים', count(*) from public.ai_generations where user_id <> '<UUID של A>';
rollback;
```
**אמור לחזור:** 0 בכל השורות. אותה בדיקה רצה בהצלחה על Postgres 16 מקומי, ב-13 טבלאות.
