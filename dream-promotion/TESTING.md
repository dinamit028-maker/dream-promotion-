כל בדיקה כוללת מה עושים, מה אמור לקרות, ומה לצלם אם זה לא קורה.
**אחרי כל בדיקה, סמנו ✅ או ❌, וצרפו צילום מסך לכל ❌.**

לפני שמתחילים, ב-Supabase:
- כל המיגרציות, מ-100 עד 3100, הורצו על המסד החי. ראו "מצב מיגרציות" ב-STATUS.md.
- `cron-stories.sql` ו-`cron-publish.sql` רצו עם אותו `CRON_SECRET` שמוגדר ב-Vercel.

## 6. אבטחה, ב-Supabase האמיתי (RLS)

ב-SQL Editor, עם ה-uuid של משתמש A (מ-Authentication ← Users). הבדיקה רצה בתוך טרנזקציה שמתבטלת, כך שלא משתנה כלום:
```sql
begin;
set local role authenticated;
select set_config('request.jwt.claims', json_build_object('sub', '<UUID של A>', 'role', 'authenticated')::text, true);
select set_config('request.jwt.claim.sub', '<UUID של A>', true);
select 'media של אחרים' as t, count(*) from public.media where user_id <> '<UUID של A>'
union all select 'content של אחרים', count(*) from public.content where user_id <> '<UUID של A>'
union all select 'טוקני רשתות (כולל שלי)', count(*) from public.social_accounts
union all select 'עלויות AI של אחרים', count(*) from public.ai_generations where user_id <> '<UUID של A>';
rollback;
```
**אמור לחזור:** 0 בכל השורות. אותה בדיקה רצה בהצלחה על Postgres 16 מקומי, ב-13 טבלאות.
